How Monte Carlo localization works

Odometry is good but it drifts: tracking wheels slip, get bumped, and read a little long or short, and every error stays in the pose for the rest of the match. MCL keeps a cloud of particles, each one a guess at where the robot is, and uses the distance sensors to keep the cloud honest. Every 50 ms it runs three steps:

  1. Predict. Move every particle by what odometry measured since last time, plus a little random noise, because odometry isn't perfect. The cloud follows the robot and spreads out a bit.
  2. Weigh. For each particle, work out what each distance sensor would read from there, and compare with what it did read. Particles that explain the readings get heavy; the rest get light. A reading nothing explains (another robot in the way) counts as an outlier, so it can't drag the cloud off.
  3. Resample. Copy heavy particles and drop light ones, so the cloud gathers where the robot really is.

The cloud's average is the estimate. When the cloud is tight and enough sensors agree with the walls, the localizer eases odometry's pose toward it, at most 4 in/s so the PIDs never see a jump. Heading always comes from the IMU.

Things odometry never sees

A bump shoves the robot 6 in without its tracking wheels turning: odometry is now wrong, and only the sensors can tell. Pick it up drops it where you click next. Recovery reaches about 18 in from the estimate (see MCL); farther than that, relocalize globally, which scatters every particle over the field (try 1500 particles).

Auto-tune the localizer

        
Searches LocalizerConfig for the settings that keep the corrected pose closest to where the robot really is, across simulated runs, starting from the MCL tab's settings. Every candidate replays the same paths with the same noise, so only the settings differ, and the winner is checked on runs it never saw.

Calibrate from the robot's logs

        
Copy the sl folder off the robot's SD card and open its logs (and its TUNE.CFG, if it has one). The robot's own readings say how noisy its sensors really are, how often they're blocked or read nothing, how old a reading is, whether a sensor's mount is off, and how far off the tracking wheels' scale is. The simulated robot gets those errors, its real paths become cases, and the search runs on that: "Your robot".
